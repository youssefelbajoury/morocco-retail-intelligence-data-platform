# Phase 19 - Prometheus + Grafana observability (completion report)

## OBJECTIVE
Deliver live, version-controlled observability for the MRI platform on top of the
existing Phase 16 operational audit model (`ops` schema + structured event log):

- a hand-rolled, zero-extra-dependency **metrics exporter** (`mri-metrics`) that turns
  `ops` views, retail PostgreSQL internals and Airflow metadata into Prometheus
  text-format metrics, **without creating a second source of truth**;
- a pinned **Prometheus + Grafana** stack behind an optional Compose `observability`
  profile (nothing heavier than ~0.5 GiB, respecting the ≤8 GiB host constraint);
- **four provisioned dashboards** (Pipeline Overview; Data Quality & Reconciliation;
  Airflow/Task Health; Data Freshness & Throughput) whose panels reference only
  real, already-existing metrics;
- promtool-validated Prometheus config with **6 alert rules**;
- a **real pipeline execution** proving metrics change end-to-end;
- full test/gate coverage and documentation (guide, metric catalog, ADR-015).

## DESIGN DECISIONS
1. **Hand-rolled exporter, no new Python runtime dependencies.** Exposition uses the
   stdlib (`http.server`); SQL uses the already-present `psycopg`. Rejected
   `prometheus-client` (a runtime dep for marginal benefit over raw text), a generic
   `postgres_exporter`, and a statsd bridge — the audit model needs custom JOIN-driven
   series that a generic exporter cannot express, and a second exporter only adds
   failure modes. Recorded in ADR-015.
2. **Bounded, label-safe series.** Metric labels are limited to
   `pipeline, stage, source, table, side, state, dag_id, datname`. Never run/batch IDs,
   filenames, or customer/product identifiers. Cardinality is fixed per dataset.
3. **Fail-safe.** A failed data source drops only its own domain metric families and flips
   `mri_exporter_last_scrape_success` to `0`; the exporter still serves self + remaining
   families. Missing Airflow credentials skip all `mri_airflow_*` series (`mri_airflow_up` 0)
   rather than breaking the scrape.
4. **Pinned images, never `latest`.** `mri-metrics:0.1.0` (built from
   `python:3.12.13-slim-bookworm` + `psycopg[binary]==3.3.6`), `prom/prometheus:v3.13.4`
   (LTS), `grafana/grafana:13.2.3`. All three verified to exist during the phase.
5. **Optional Compose profile.** The stack is `--profile observability`-gated; with the
   profile off there is zero runtime impact on the data platform.

## FINDINGS & FIXES
- **FIND-01 (DAG defect, surfaced by this phase):** `audit_airflow_run` failed for
  **manual** triggers with `UndefinedError: 'data_interval_start' is undefined` because
  manual runs have no data interval. This also explains 4 of the 5 historical `failed`
  DAG runs. The task was retried (retries=2, 5-min backoff → ~10 min gap before failing).
  **Fix:** `--logical-date "{{ data_interval_start | default('') }}"` in
  `airflow/dags/morocco_retail_pipeline.py`. Verified by re-running the task against the
  same run: rendered `--logical-date ""`, recorded `airflow/dag_run status=success`, exit 0,
  state success. The bookend event was then synced and appears as
  `mri_pipeline_runs{pipeline="airflow"}`.
- **WARN-01 (host port conflict):** a native Windows `postgres` process (PID 3540) listens
  on 0.0.0.0:3000, colliding with Grafana's default host port. Not a Grafana fault — the
  container stayed healthy and the conflict is environmental. Verification stack used
  `GRAFANA_PORT=3001`; the committed default remains 3000. See `docs/observability/
  prometheus-grafana.md` troubleshooting.
- **WARN-02 (orphan-compose warning):** running the observability profile without the
  Airflow compose file prints Docker's "orphan containers" warning for the running Airflow
  services. Benign — they share `mri-net` and the exporter reaches `airflow-postgres:5432`
  when the `AIRFLOW_POSTGRES_*` credentials are present.
- **WARN-03 (Grafana plugin auto-install):** Grafana 13 installs its default background
  plugins (`grafana-pyroscope-datasource`, ...) on first boot. Harmless; disable in the
  provisioning dir if a strictly-empty plugin set is required.
- **WARN-04 (bookend duration):** the DAG bookend event carries no `duration_ms`, so
  `mri_pipeline_duration_ms_avg{pipeline="airflow"}` is 0 for a single event.

## DASHBOARDS (4 × 8 panels)
- `mri-pipeline-overview` — run counts/success rate per stage, last-run outcome, rows
  read/written/rejected, duration avg/p95, overall success %.
- `mri-data-quality` — storage-side reconciliation per target table, balanced flag,
  row-count side-by-side silver vs warehouse.
- `mri-airflow-health` — DAG-run history by state, task-instance history by state, last DAG
  run timestamp, DAG-level success (from metadata DB).
- `mri-freshness-throughput` — staleness seconds per source, last success timestamp, DB
  size/connections/cache hit ratio, scrape health.

## ALERT RULES (6)
1. `MRIExporterDown` — `mri_exporter_last_scrape_success == 0` for 1m.
2. `MRIWarehouseReconcileOffTrack` — `mri_warehouse_reconcile_balanced == 0`.
3. `MRISourceStale` — `mri_source_freshness_seconds > 86400` (24h) with `source` label.
4. `MRIPipelineLastRunFailed` — `mri_pipeline_last_run_succeeded == 0` for 5m.
5. `MRIDatabaseConnectionSaturation` — `mri_postgres_connections > 0.9 * 100` (provisioned
   pool 100) sustained 5m.
6. `MRIDiskspaceSaturation` — `mri_postgres_database_size_bytes > 0.9 * 2GiB`.
