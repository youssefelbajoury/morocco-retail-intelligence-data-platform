# Phase 25 - Superset native-filter interactive verification (browser E2E)

Status: **PASS — acceptance criterion AC11 (interactive native-filter behaviour) is now verified**
Date: 2026-10-14
Author: Phase 25 verification pass

## 1. OBJECTIVE

Close the single remaining unverified acceptance item (AC11) from the Phase 21
final acceptance audit: prove **in a real browser** that the Superset dashboards
load and that the native filters actually drive the charts — selecting a filter
value changes the underlying chart data, and clearing the filters restores the
original values. Add a reproducible browser test suite and a dedicated developer
command, run it against the live stack, and record the evidence.

## 2. BROWSER TOOL / VERSION

- Driver: **Playwright for Python 1.64.0** (added to the `dev` dependency group).
- Browser: **Microsoft Edge 155.0.4283.45**, launched via `channel="msedge"`
  (uses the locally installed Edge, so **no browser download** is required).
- Overrides: `MRI_E2E_BROWSER_CHANNEL=""` falls back to Playwright's bundled
  Chromium; `MRI_E2E_HEADLESS=0` runs headed for debugging.
- Test runner: **pytest 9.1.1** on **CPython 3.12.13**.

## 3. TEST ENVIRONMENT

- Host: Windows 11, host-local development deployment (all ports bound to
  `127.0.0.1`).
- Superset: `http://localhost:8088` (`mri-superset`, Superset 6.1.0, SQLite
  metadata, `GET /health` -> 200). Backing PostgreSQL `localhost:5433` (`retail`).
- Credentials: read from the git-ignored `.env`
  (`SUPERSET_ADMIN_USER`/`SUPERSET_ADMIN_PASSWORD`); no secret is printed,
  reported or committed. The browser session is a normal UI login; no warehouse
  data is mutated (assertions are read-only — they observe chart responses).
- Suite location: top-level `e2e/` (deliberately **outside** `tests/`, whose
  `testpaths = ["tests"]` keeps it out of the default `uv run pytest` run).
- Command: `make e2e` (i.e. `uv run pytest e2e`). Everything the suite needs is
  documented in the module docstrings.

## 4. FILTER SCENARIOS

Each scenario drives one native `filter_select` filter on one dashboard and
observes the KPI chart response from `POST /api/v1/chart/data`:

| # | Dashboard | Filter | Options exposed | KPI chart |
|---|-----------|--------|-----------------|-----------|
| 1 | Sales Performance | Channel | E-commerce, In-store, Mobile app | Net Revenue |
| 2 | Sales Performance | Category | beaute, boissons, epicerie, frais, menage, produits_laitiers | Net Revenue |
| 3 | Sales Performance | Region | Tanger-Tetouan-Al Hoceima (single value) | Net Revenue |
| 4 | Inventory Health | Stock Status | in_stock, low, out_of_stock | Stock Value |
| 5 | Executive Overview | Category | beaute, boissons, epicerie, frais, menage, produits_laitiers | Revenue |
| 6 | Procurement | Category | beaute, boissons, epicerie, frais, menage, produits_laitiers | Purchase Cost |
| 7 | Platform Health | Source | 14 values (calendar … stores) | Pipeline Loads |

The interaction is: capture the KPI baseline -> open the filter Select, read the
option labels, select the first option, press **Apply** -> capture the filtered
KPI -> press **Clear all** + Apply -> capture the restored KPI.

## 16. WARNINGS

- **W1 — Region filter is degenerate.** Because all `fact_ventes` rows share the
  single `region_name` value `Tanger-Tetouan-Al Hoceima`, the Region filter
  exposes one option and cannot narrow any chart. The test encodes this honestly:
  for a single-valued filter it asserts the KPI is **unchanged** rather than
  asserting a narrowing that cannot happen.
- **W2 — Root cause of the empty filters (fixed).** Superset 6.1.0 needs the
  `datasetId` on a native `filter_select` target to resolve filter option values;
  the seeder previously emitted only `datasetUuid`, so every filter Select showed
  a single `<NULL>` option. Fixed in `seed.py` and guarded by a `verify.py`
  regression assertion.
- **W3 — Filter controls render slowly (~10–25 s)** on this host; the helpers
  poll rather than sleep a fixed amount, so runs are longer (≈5:50) but stable.
- **W4 — Not in the default test run.** By design, `uv run pytest` (testpaths
  `tests/`) never launches a browser; run `make e2e`. If Superset is down the
  suite **skips** with a clear message.
